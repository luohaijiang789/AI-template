# 把这套规范用到其他项目

最小接入只需要：**基础规范 + 目标项目背景**。模型和实践在遇到具体问题时再选取。

## 三步接入

1. 从[基础规范](基础规范.md)找到通用提示词，复制其中的 `text` 代码块。
2. 填写[项目补充模板](项目补充模板.md)，只保留影响该项目工作的字段。
3. 将两段内容放进目标项目使用的指令入口；已有指令文件时先阅读，再合并适用规则，保留目标项目约定。普通对话可直接粘贴两段文字。

目标工具需要什么文件名、能否自动加载，应按其实际能力确认。添加指令不会自动提供文件、联网、工具或持久记忆能力。

## 按任务扩展

| 使用方式 | 加载内容 | 完成条件 |
|---|---|---|
| 只改善回答 | 通用提示词，加读者和表达偏好 | 简单问题清楚，复杂回答不遗漏条件 |
| 接入一个项目 | 通用提示词，加项目背景、结构、工具与验收 | AI 能识别目标与已有组织方式 |
| 做研究、开发或架构任务 | 以上内容，加[场景选择](场景选择.md)中的必要材料 | 一次真实任务能完成并验证 |

示例：[知识库项目接入](接入示例/知识库项目.md)。

## 接入后检查

- 用一个简单问题检查是否出现不必要的开工流程或图表。
- 用一个复杂任务检查是否先读取项目背景、复用现有结构并明确验收。
- 用一个未知或未执行状态检查是否诚实说明。
- 检查目标项目的路径、命令、分支和权限是否真实；未提供的内容保持未知。

以上为接入检查建议，不能只因指令文件存在就宣布行为效果通过。可借用[固定案例](../评测/固定案例/README.md)开发检查，并补充该项目真实任务。

## 更新与边界

手工复制后，目标项目持有自己的版本，不会自动跟随本库更新。建议记录来源版本或提交、复制日期和本地调整；升级时比较变化，再做对应回归。

本仓库根目录的 [AGENTS.md](../AGENTS.md)包含本项目维护规则。接入其他项目时，使用本目录流程，不应直接搬用其中的目录、主干与推送约定。
