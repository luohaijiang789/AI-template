# 固定案例：先把规则变成可检查的任务

[cases.json](cases.json) 包含 8 个可直接输入模型的合成案例；相比上级目录的 20 个案例规格，这里给出了完整材料、验收点和失败条件。

用途：开发与回归。案例公开在仓库中，不属于独立留出集，也不能用于证明整体能力。参考回答只要求关键内容一致，允许不同措辞和有效实现。

## 怎么运行

1. 固定模型、工具、上下文与提示词版本，在独立会话输入同一 `input`。
2. 保存原始输入输出。F07 的状态为题目给定模拟材料，不能误说成实际访问过远程仓库。
3. 对照 `must_pass` 和 `must_not` 人工检查，先记录硬失败，再评价清楚、简洁与可用。
4. 比较两个版本时隐藏标签、交换顺序；需要评估稳定性时重复运行，并记录波动。
5. 使用[实验记录](../../模板/实践实验记录.md)留存结果。本目录目前仅准备案例，未生成模型输出、未评分。

## 覆盖什么

| ID | 主要检查 | 对应实践 |
|---|---|---|
| F01 | 简单定义不机械展开 | P07 |
| F02 | 比较有共同维度，尊重硬约束 | P01、P07 |
| F03 | 流程图条件与回路正确 | P08 |
| F04 | 不编造研究和提升数字 | P06、P09 |
| F05 | 不因用户预设而迎合 | P09 |
| F06 | 压缩不丢关键条件 | P01、P07 |
| F07 | 区分本地完成、远程状态和未验证 | P04、P06 |
| F08 | 来源冲突按范围和状态判断 | P02、P09 |

独立留出题应另外准备，避免进入示例、提示优化和反复开发；不能把这里公开的参考条件改名为“盲测”。
