# 规则维护与状态

目的：知道规则在哪里维护、是否已采用、有什么证据，避免重复更新和误判效果。

## 各类内容的维护位置

| 内容 | 主维护位置 | 其他文件如何使用 |
|---|---|---|
| 通用价值与取舍 | [核心原则](核心原则.md) | 提示词和说明提炼，不独立发明相反规则 |
| 工作前准备与架构 | [工作架构](工作架构.md) | 模板提供填写格式，AGENTS.md 指向规范 |
| 表达与图表 | [表达选择](表达选择.md) | 卡片按内容应用，案例展示，不改写成全场景强制要求 |
| 卡片必备内容 | [模型卡片模板](../模板/模型卡片.md)及[实践维护约定](../优秀实践/README.md) | 索引负责检索，AGENTS.md 引用要求 |
| 本项目 Git 约定 | [协作与提交规范](../项目/协作与提交规范.md) | 本项目指令引用；跨项目补充由目标项目填写 |
| 可复制通用提示词 | [核心提示词](../模板/核心提示词.md) | 复用入口只链接，不保存第二份正文 |
| 本仓库执行入口 | [AGENTS.md](../AGENTS.md) | 指定先读什么、如何维护，不作为跨项目通用包 |

提示词是对规范的精简应用版本，维护规范时检查提示词是否仍一致；为了便于复制允许必要提炼，不要求运行时读取所有原文。示例和研究不是另一个指令来源。

## 行为采用状态

| 状态 | 含义 | 需要记录什么 |
|---|---|---|
| 候选 | 值得试用，尚未决定作为共用行为 | 来源、适用范围、验证方式 |
| 已采用 | 团队选择作为当前约定 | 决定、范围、取舍；不能据此宣称有效 |
| 已验证 | 在明确条件与样本上获得结果 | 版本、原始结果、判定方式和局限 |
| 已弃用 | 不再推荐或已被替代 | 原因、替代入口，保留必要历史 |

来源阅读状态单独记录为“相关正文、摘要、检索摘要、无法访问”等。**读过正文不等于行为已验证；已采用也不等于效果已证实。**

当前：共用规范为已采用的项目约定；模型和实践的定义核验见各卡片，其组合与实际效果仍需任务验证。现有文档检查只证明所检查的结构和语法，不能把整个项目标为“已验证”。

新增行为先登记适用条件与证据；状态确实变化时更新相关页面。重要改变写决策记录，小型修订用清楚的 Git 提交说明，不为每段内容增加重复状态表。
