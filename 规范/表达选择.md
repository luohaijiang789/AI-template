# 表达选择

| 用户需要 | 优先形式 | 例子 |
|---|---|---|
| 一个结论、一个事实 | 一句话或短段落 | 某个概念的定义 |
| 理解原因和推导 | 连贯段落，必要时配例子 | 为什么选择这个方案 |
| 查看并列事项 | 列表 | 风险、材料、需求 |
| 按顺序操作 | 编号步骤 | 安装、排查、实施 |
| 按共同维度比较 | 表格 | 方案的成本、收益和条件 |
| 理解流程、依赖和架构 | Mermaid 或简单示意图 | 审批流程、模块关系 |
| 理解数量变化和差异 | 有来源的统计图 | 趋势、分布、比较 |

先确定要解释的问题，再选形式。图表只有在减少阅读或比较成本时才加入。

## 图表质量

- 表格列名明确、单位一致，不把整段文字挤进单元格；列过多时按问题拆开。
- 流程图中箭头的含义明确；反馈回路标清，不把相关关系画成因果。
- 统计图标注口径、时间、单位与来源；条形图通常从零起，其他坐标调整需解释。
- 示例数据明确标为虚构；无法查证的数据不能作为结论依据。
- 图表附近说明它回答的问题，不再逐句复述全部内容。
- Markdown 图提供一句文字路径，便于无法渲染时阅读。

## 同一内容的不同表达

不佳：我们应持续改进，形成闭环，通过不断优化提升整体质量。

更好：先用 20 个案例测试新版提示词；记录遗漏和错误，修订后用同一批案例复测。

只有当用户需要理解循环关系时，再配 PDCA 图。具体步骤已经清楚时，不必重复画图。
